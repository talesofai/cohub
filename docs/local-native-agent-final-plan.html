01 / Decision

ACP control, native execution, one workspace anchor.

ACP carries session control and portable updates while the provider keeps its native tools, configuration, credentials, model settings, and session files. Workspace bytes and transcript projections share an execution attempt, but never share a storage format.

  • Native providers stay native. Their prompts, tools, plugins, credentials, model settings, and native sessions are untouched.
  • Web stays cloud-first. Web and mobile continue through the existing apps/agent execution path.
  • ACP owns local session control. The Agent opens a fenced runtime peer; locald forwards official ACP stdio without provider-specific Cohub tools.
  • Legacy hooks never wait for network. They remain local IPC and durable spooling compatibility only.
  • Cloud state remains server-owned. Locald never writes Postgres, Redis, /sessions, or an internal worker API.
  • Incomplete data fails closed. An unstable scan, unknown provider schema, or unverified object cannot become a successful result.
  • Offline is explicit. An intentional offline run requires a bounded reservation; accidental offline changes are stale candidates.
  • History is not a file sync problem. Provider transcripts are adapted into portable CoHub logical entries.
  • Conflicts remain recoverable. Both workspace versions and their base stay addressable until resolution and retention complete.
02 / System map

The cloud remains the product authority.

Locald materializes the replica and hosts the ACP adapter boundary. It does not become a second cloud control plane and it does not turn a local folder into a remote mount.

Local boundary

The ACP adapter sees the provider's native process and local replica only. Runtime and lease metadata are consumed by locald, then removed before provider forwarding. Absolute roots and provider home paths never cross the API.

Cloud boundary

The API authenticates the device and Space membership. Workers verify bytes and schemas. Agent code reads only committed, visible transcript entries and a verified cloud workspace.

03 / User flows

Every handoff has a visible boundary.

The normal path is fast because local hooks use cached permit state. Readiness that requires network work is explicit and can be prepared before the provider prompt.

01

Attach a cloud Space

cohub workspace attach <space> --root <dir> enrolls the device, records separate workspace and session consent, compares the tree, and refuses a divergent non-empty root without an explicit choice.

No destructive default
02

Start a local ACP runtime

locald connects the registered runtime to Gateway and launches the official Pi, Claude, or Codex ACP adapter only for an authorized peer. The provider receives the attached replica as its working directory.

Fenced ACP peer
03

Seal one execution attempt

The accepted prompt allocates an executionAttemptId and records the workspace base. The ACP command ledger, ordered event receipts, and local workspace candidate share the same attempt ID.

Shared correlation
04

Continue from Web or mobile

Web creates a normal cloud agent turn. It waits for the cloud workspace to be current and for the local ACP transcript visibility barrier to finish. Cloud execution never injects a prompt into a provider-owned local session.

Cloud-first
05

Resume the ACP session

The Agent asks the adapter to resume or load its provider-owned session. If continuity cannot be established after durable events exist, the turn stops with an explicit reconnect requirement.

No silent fork
06

Use offline mode deliberately

cohub workspace offline enable --max-duration <duration> obtains a bounded reservation while connected. On reconnect, the candidate reconciles from its recorded base. Without a reservation, local work has no ownership claim.

Explicit reservation
04 / Workspace replication

Snapshots, not mounts.

Each replica is a real filesystem. The server promotes only verified snapshots and resolves divergence against the last common base.

B

Common base

The last canonical snapshot applied to both sides. It is the only valid starting point for a three-way decision.

L

Local candidate

A complete, immutable manifest observed on the local replica. It carries its base snapshot, policy version, and attempt ID.

C

Cloud canonical

The current server-approved tree. Promotion happens only after cloud apply and a verified rescan.

attached->scanning->candidate->verified->canonical

Manifest v1

  • Paths are relative, slash-separated, NFC-normalized, UTF-8 byte sorted, and never root-escaping.
  • Directory entries are included so empty directories survive.
  • Regular files use whole-file SHA-256 identity; mtime and size only accelerate scans.
  • Symlinks must be relative and remain inside the replica root. Sockets, devices, FIFOs, and unsafe links are rejected.
  • .git/ and .cohub/system/ are hard exclusions.
  • Policy version and effective excludes are part of snapshot identity.

Transfer ladder

prepare manifest->upload missing blobs->verify bytes->semantic ACK

Small objects use a single signed PUT. Larger objects use resumable multipart transfer. The final whole-file hash remains the logical identity. A partial object is never visible as a workspace file.

Safe apply and deletion rules
  1. Validate every plan path again at the target root.
  2. Stage and verify blobs before they can replace visible files.
  3. Recheck precondition hashes and record a rollback journal.
  4. Apply directories, atomic file renames, executable bits, and safe symlinks.
  5. Fsync where supported, rescan, verify the target tree hash, then ACK applied.
  6. An incomplete or unstable scan cannot generate a deletion plan. A large deletion wave is blocked for explicit confirmation.
Git semantics

Git metadata is handled through bundle and ref-aware operations, not byte synchronization of .git. Fast-forward is allowed only when the old head is an ancestor and preconditions match. Divergent refs become git_ref conflicts. Index, stash, credentials, hooks, reflogs, worktree administration, and LFS object stores remain local.

Reader rule: Cloud Agent context, fork provisioning, Web projection, and cursor calculation all use the same visibility filter. A later marker cannot reveal an earlier unmarked batch.

Portable logical sequence
user->assistant toolCall->toolResult->assistant final
  • Pi remains the CoHub JSONL representation even when the source is Claude or Codex.
  • Tool results are independent records and must reference a prior deterministic tool call.
  • Exactly one primary user prompt is allowed per imported CoHub turn.
  • Provider system/developer/config/hidden state and reasoning signatures never become model context.
  • If a provider fact cannot be represented without inventing context, quarantine or degrade explicitly.
Automatic fork rules
  • Fork when the CoHub leaf or branch epoch advanced beyond the native binding anchor.
  • Fork when the provider rewound or resumed an older native branch.
  • Anchor at the latest common completed mapped turn, never at a timestamp alone.
  • Transcript fork and workspace reconcile are separate: a native candidate still reconciles against the current Space canonical snapshot.
  • Never delete or rewrite an already visible CoHub turn.
06 / Coordination

Transport is at-least-once. Product application is exactly-once.

Postgres is the durable coordination authority. Redis and BullMQ improve latency, but every accepted operation can be rediscovered from database state.

Workspace writer

One Space-level fenced lease identifies local, cloud, local_offline_reservation, or a controlled sync apply. Every mutation carries the lease epoch and attempt capability.

none->prepared->running->sealed

Session writer

One session-level durable lease is paired with a PostgreSQL session-level advisory lock. Cloud append, native ingest, and fork provisioning share the same physical serialization.

ready->locked->fsynced + projected

Execution attempt barrier

prepared->running->workspace_sealed+transcript_sealed->completed

An attempt cannot complete until every required barrier is terminal and compatible. Metadata-only attempts set transcript_required=false; disabled mirror creates no native ingest.

Queue and recovery policy
  • cohub-workspace-sync and cohub-native-agent-ingest use deterministic job IDs.
  • Database sweepers re-enqueue committed non-terminal rows after Redis or worker loss.
  • Control work such as preflight, abort, and lease renewal has a separate high-priority lane from bulk transfer.
  • Cheap online notifications release parked work; expensive full scans are throttled and coalesced.
  • Retries never rewind a terminal applied, completed, cancelled, or quarantined row.
07 / Security and privacy

Least authority at every boundary.

Device access, workspace content, native identity, and provider credentials are separate capabilities. A local folder attachment does not grant a broad cloud file or session export.

Identity

  • OAuth/device-code or loopback pairing; no permanent token in shell history.
  • Refresh credential stored in the OS keychain and returned only during enrollment.
  • Device revoke immediately blocks new ingest, apply, and lease acquisition.
  • Native session, turn, message, tool, and path identities use domain-separated HMAC with Space/replica scope.

Content

  • Raw native transcript files, provider system/developer prompts, hidden context, and credentials never upload.
  • Likely credential files use Space-level exclude_with_warning by default.
  • Absolute local roots never reach the server; only labels and fingerprints are stored.
  • Untrusted imported content is data, never CoHub control input.

Prompt integrity: CoHub does not inject its system prompt, tool definitions, model settings, hidden context, or cloud prompts into Pi, Claude Code, or Codex. The only provider-visible intervention is an explicit strict-mode preflight block when the workspace handoff is unsafe.

08 / Delivery sequence

One approval. Seven reviewable milestones.

Each milestone has its own exit gate and can be paused without deleting local state, accepted objects, or canonical cloud data.

  1. M0

    Protocol and writer foundations

    Protocol v1 types, JCS fixtures, execution attempts, migrations, advisory-lock writer, transcript reader/committer, outbox, queues, and disabled enforcement hooks.

    Exit gateExisting cloud JSONL and checkpoint behavior remain equivalent. Hash and cursor properties are deterministic.
  2. M1

    Cloud snapshot service and locald skeleton

    Policies, cloud scan, device enrollment, keychain state, SQLite WAL state, watcher, bounded scanner, spool, attach, and cloud-to-local bootstrap.

    Exit gateEmpty-root attach is identical on supported platforms. Kill during apply leaves no partial visible tree.
  3. M2

    Bidirectional workspace reconciliation

    Candidate upload, whole-file blobs, three-way planner, safe apply, conflicts, leases, offline reservation, Git bundle/ref semantics, and cloud mutation integration.

    Exit gateLocal and cloud changes converge; conflicts preserve both sides and block unsafe execution.
  4. M3

    Native ingest core and Pi

    Native ingest API, local collector, receipts, hidden JSONL entries, commit markers, DB projection, outbox, exact Pi adapter, continuation, and automatic fork.

    Exit gateOne Pi turn with tools appears exactly once and continues from cloud. Pre-marker entries remain invisible.
  5. M4

    Claude Code

    User-scoped hooks, prompt IDs, delayed transcript reconciliation, StopFailure, compaction, subagent metadata, and version fixtures.

    Exit gateLagging transcript is handled without false success; unsupported format is explicit degradation.
  6. M5

    Codex

    User-scoped hooks, trust guidance, turn IDs, concurrent hook ordering, optional tested parser, compaction, interruption, and recovery.

    Exit gateNormal Codex turns mirror; transcript drift disables only the parser, not the hook-reconstructed path.
  7. M6

    Production rollout

    Dashboards, alerts, GC, user services, shadow scanning, binary/CDN workflow, compatibility matrix, and provider feature flags.

    Exit gateCanary passes all acceptance scenarios and zero-silent-loss gates.

10 / Approval gates

The final contract.

Approval authorizes implementation in the sequence above. It does not authorize silent compatibility, implicit ownership, or raw provider-data export.

  1. Native integration is a local-to-CoHub mirror, not provider session-file synchronization.
  2. Web continuation never mutates native history; later native continuation forks at a verified common completed turn.
  3. Workspace online execution is single-writer coordinated. Intentional offline work requires a bounded reservation.
  4. Workspace files use canonical snapshots and three-way reconciliation. .git uses bundle/ref-aware semantics.
  5. CoHub JSONL and Postgres remain server-owned and are repaired through an immutable ingest journal and commit marker.
  6. Pi ships first at exact fidelity; Claude and Codex publish only the fidelity their tested adapter supports.
  7. Policy drift, incomplete scans, hidden transcript batches, unsupported schemas, and conflicts block or degrade explicitly.
  8. Workspace consent and session-mirror consent are separate. Metadata-only mode creates no product transcript.
  9. executionAttemptId joins workspace and transcript outcomes. Remote apply never writes into an active local provider cwd.

What the Lody review changed

The review reinforced the boundary decisions rather than changing the substrate. Adopted lessons are capability negotiation, durable-vs-delivery separation, semantic IDs, bounded recovery, marker-first side effects, payload budgets, lazy metadata indexing, and separate control/bulk lanes. Loro CRDT and Streams are not required dependencies for this CoHub implementation.

Borrow

Versioned capabilities; ack-then-execute dispatch; tool/event aggregation; digest and prefix reconciliation; atomic markers; re-read under lock; bounded retry and backpressure.

Do not copy

A full CRDT dual-author workspace plane, Streams as workflow authority, provider loadSession as a generic parser, same-user socket identity as complete auth, or product-specific prompt injection.
